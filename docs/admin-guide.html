sbproxy — Triển khai từng bước

Làm tuần tự từ trên xuống: tải firmware → backup → update → cài đặt → cấu hình → cài agent → kiểm tra → vận hành. Mỗi bước có nút chuyển bước ở cuối.

★ Best practices — đọc trước khi bắt đầu

  • Luôn cắm LAN dây dự phòng khi động vào firmware/mạng — hỏng WiFi vẫn SSH vào cứu được.
  • Tải backup RA MÁY TÍNH trước mỗi lần update firmware — backup trên router mất sạch nếu reflash/brick. Xem Bước 3.
  • Verify sha256 mọi image firmware trước khi flash. Giữ sẵn 1 image “biết-chạy-tốt” trên máy.
  • Ghi lại phiên bản firmware hiện tại (cat /etc/openwrt_release) trước khi đổi.
  • Xem trước bằng DRYRUN=1 trước khi apply.sh. Test 1–2 SSID rồi mới nhân lên 20–30.
  • Không expose uhttpd/agent/SSH/LuCI ra WAN. Giữ token agent bí mật. Xem Bước 9.
  • Chốt số SSID theo iw list (giới hạn BSSID), đừng giả định cứng 30. Xem Bước 6.

Tổng quan kiến trúc

WiFi Alpha ─(br-w1, 192.168.11.0/24)─┐ WiFi Bravo ─(br-w2, 192.168.12.0/24)─┤ nftables TPROXY theo iifname WiFi ... ─(br-wN, ...)─────────────┘ │ (mỗi WiFi → cổng 12000+idx) ▼ sing-box (tproxy in → socks out) ──▶ WAN UI http://router/sbproxy/ ─▶ CGI /cgi-bin/sbproxy ─▶ apply/set-sock/rollback sbproxy-healthd (procd) ─ curl socks5h ─▶ /tmp/sbproxy-health.json (latency realtime)

BƯỚC 2Tải firmware & verify

BƯỚC 3Backup — RA MÁY TÍNH (trước khi update)

Vì sao bắt buộc
Backup mặc định nằm ở /root/sbproxy-backups/ trên router — nếu update lỗi phải reflash/brick, backup đó mất theo. Phải có một bản trên máy tính.
# Cách 1 — UI: 🗂 Backup / Rollback → ⭳ Về máy
# Cách 2 — LuCI: System → Backup/Flash Firmware → Generate archive
# Cách 3 — từ máy tính (PowerShell):
scp -r root@192.168.1.1:/root/sbproxy-backups .\sbproxy-backups
sh scripts/backup.sh before-fw-upgrade    # (nếu đã cài project) tạo mốc

Đảm bảo backup chuẩn OpenWrt giữ được config sbproxy (đã tự đăng ký bởi install-deps/install-agent):

cat /etc/sysupgrade.conf   # phải có /etc/sing-box/, /etc/sbproxy.nft, /etc/sbproxy/, config/

BƯỚC 4Update / flash firmware

Cách A — U-Boot recovery (an toàn nhất, khuyên dùng khi đổi họ firmware)

  1. Tắt nguồn. Máy tính đặt IP tĩnh 192.168.1.2 / 255.255.255.0.
  2. Giữ Reset, cấp nguồn, giữ tới khi đèn nháy nhanh rồi thả.
  3. Mở http://192.168.1.1 → U-Boot → upload image → flash → chờ reboot.

Cách B — Local Upgrade từ GL GUI

http://192.168.8.1 → System → Upgrade → Local Upgrade → chọn image → BỎ TICK “Keep settings” khi đổi họ firmware → Upgrade.

Giữ settings?
Nâng cấp cùng họ firmware có thể “keep settings”. Đổi họ (GL→OpenWrt) thì không giữ được → sẽ khôi phục bằng backup ở Bước 12 hoặc cấu hình lại từ Bước 7.

BƯỚC 9Cài agent điều khiển (kiến trúc B)

Cho UI áp config trực tiếp + health-check latency realtime.

cd /root/sbproxy
sh agent/install-agent.sh
# → cài curl/jq, tạo /etc/sbproxy/token, đặt CGI /www/cgi-bin/sbproxy,
#   self-host UI /www/sbproxy/, chạy daemon sbproxy-healthd. In ra URL + TOKEN.

Mở http://<router>/sbproxy/ → 🔌 Kết nối router → dán token. Cấu hình daemon ở /etc/sbproxy/env:

BiếnMặc địnhÝ nghĩa
INTERVAL15Giây giữa các lần probe.
SLOW_MS800Ngưỡng coi là “chậm”.
PROBE_URLgstatic /generate_204URL đo latency.
PROBE_TIMEOUT8Timeout mỗi probe (giây).

9.1 Token điều khiển là gì?

Là một chuỗi bí mật ngẫu nhiên (bearer token — kiểu "mật khẩu máy-với-máy"), do install-agent.sh sinh ra và lưu tại /etc/sbproxy/token trên router (chmod 600). UI trong trình duyệt gắn token vào header X-SB-Token mỗi request; agent so khớp mới cho thực thi.

Bản chất
Đây là bí mật dùng chung, KHÔNG phải hệ đăng nhập. Ai cầm token là có toàn quyền router (apply/rollback/đổi sock…), không phân biệt người, không hết hạn, không ghi "ai làm gì". Cần phân quyền theo người → dùng Cloud (Bước 15).

9.2 Bảo mật token

  • Không expose agent/uhttpd ra WAN — chỉ LAN/VLAN quản trị (biện pháp quan trọng nhất).
  • Chặn SSID khách chạm tới UI/agent (firewall input zone khách = reject cổng admin).
  • Ưu tiên HTTPS nội bộ cho uhttpd nếu LAN nhiều người (HTTP để token đi dạng rõ trong mạng).
  • Giữ quyền file /etc/sbproxy/token = 600 (chỉ root). Trình duyệt lưu token trong localStorage → khoá máy, đừng paste trên máy chung/lạ.
  • Chỉ paste vào UI của chính router (http://<router>/sbproxy/), không dán vào web lạ.

9.3 Quên / lấy lại / xoay token

Còn SSH vào router → chỉ cần đọc lại file, token không bị mất:

cat /etc/sbproxy/token          # in ra token hiện tại → copy, paste lại vào UI

# kiểm tra token có hoạt động:
TOKEN=$(cat /etc/sbproxy/token)
curl -H "X-SB-Token: $TOKEN" http://192.168.1.1/cgi-bin/sbproxy?action=status

Nghi lộ / muốn đổi token mới (xoay):

head -c 18 /dev/urandom | hexdump -v -e '/1 "%02x"' > /etc/sbproxy/token
echo >> /etc/sbproxy/token
chmod 600 /etc/sbproxy/token
cat /etc/sbproxy/token          # token MỚI → paste lại vào UI (token cũ lập tức vô hiệu)
# hoặc: rm /etc/sbproxy/token && sh agent/install-agent.sh   (chạy lại sẽ sinh token mới)
Không còn SSH và cũng quên token?
Vào lại router bằng LAN dây (SSH), hoặc Failsafe để mount rootfs rồi cat /etc/sbproxy/token. Token luôn nằm trong file trên router — không mất trừ khi wipe cấu hình.
Mixed-content
Chế độ Live chỉ chạy khi mở UI qua http từ chính router (trình duyệt chặn https→http). Với điều khiển từ xa an toàn hơn, dùng Cloud (Bước 15) — có tài khoản riêng + RBAC + device key (đổi bằng nút Rekey nếu lộ).
Muốn điều khiển từ xa / nhiều router / login riêng?
Agent LAN này chỉ dùng trong mạng router (hoặc qua VPN). Để quản từ xa qua web có tài khoản & phân quyền, xem Bước 15 · Điều khiển từ xa (Cloud).

BƯỚC 12Rollback & cứu router treo/brick

MứcLệnh / thao tácKhi nào
1sh scripts/rollback.sh --list · rollback.sh [tên]Quay lui cấu hình.
2sh scripts/uninstall.shGỡ sạch phần project.
3sysupgrade -r <backup>.tar.gz && rebootUCI hỏng nặng.
4LAN dây → Failsafe → U-BootMất kết nối / brick.

Router treo / brick sau update — cứu bằng U-Boot (GL-MT6000)

  1. Mềm: LAN dây → SSH → sh scripts/rollback.sh.
  2. Failsafe (OpenWrt): reboot, bấm Reset khi đèn nháy → máy IP 192.168.1.2 → SSH root@192.168.1.1 (không mật khẩu) → mount_root rồi rollback, hoặc firstboot && reboot (reset về mặc định).
  3. U-Boot web (cứu brick): tắt nguồn → máy IP 192.168.1.2 → giữ Reset khi cấp nguồn tới khi đèn nháy nhanh → http://192.168.1.1 → upload image sạch → flash.
Khôi phục backup đã tải về máy
scp .\sbproxy-<tên>.tar.gz root@192.168.1.1:/tmp/
ssh root@192.168.1.1 "sysupgrade -r /tmp/sbproxy-<tên>.tar.gz && reboot"
# hoặc LuCI: System → Backup/Flash → Restore → upload .tar.gz

Firmware/flashBrick → U-Boot (Bước 12). sha256 lệch → tải lại. Mất SSID sau nâng cấp → apply.sh.

BƯỚC 16Bảo mật & chống lộ (checklist)

Ba nhóm "lộ" cần chặn: (A) lộ danh tính/IP thật của người dùng qua proxy, (B) lộ quyền điều khiển router/hệ thống, (C) lộ dữ liệu nhạy cảm (mật khẩu sock/wifi, DB).

A · Chống lộ danh tính / IP thật

Kênh lộTrạng tháiCách bịt
IPv6 bypass (nguy hiểm, dễ quên)⚠️ Chưa xử lý ở v0.1nftables tproxy chỉ bắt IPv4 → client có IPv6 sẽ ra thẳng, lộ IP thật. Tắt IPv6 trên SSID khách: uci set dhcp.wIDX.dhcpv6='disabled'; uci set dhcp.wIDX.ra='disabled' (mỗi idx) rồi uci commit dhcp; /etc/init.d/odhcpd restart. Hoặc tắt IPv6 WAN.
DNS leak⚠️ v0.1 DNS qua dnsmasq → có thể lộÉp DNS ẩn danh: uci add_list dhcp.@dnsmasq[0].server='1.1.1.1'; uci set dhcp.@dnsmasq[0].noresolv='1' (tốt hơn: DoH qua https-dns-proxy, hoặc bật khối dns trong sing-box đi qua proxy).

Rò khi proxy chết✅ Fail-closedZone khách forward=REJECT → sing-box/tproxy chết thì client mất mạng chứ không ra thẳng lộ IP. Đừng thêm rule forward guest→wan.

B · Chống lộ quyền điều khiển

  • Không đưa quản trị ra WAN: uhttpd/agent/LuCI/SSH chỉ nghe LAN/VLAN quản trị. Đây là biện pháp quan trọng nhất.
  • Router: mật khẩu root mạnh; ưu tiên SSH key + tắt đăng nhập mật khẩu (uci set dropbear.@dropbear[0].PasswordAuth='off'); đổi mật khẩu mặc định.
  • Token agent (9.1–9.3): bí mật dùng chung = toàn quyền → LAN only, file 600, xoay khi nghi lộ.
  • Cloud: chạy sau HTTPS reverse proxy (HTTPS=1); superuser chỉ tạo qua seed.js; cấp quyền tối thiểu + giới hạn router cho từng user; device key lộ → Rekey; cân nhắc khoá đăng nhập sai nhiều lần + 2FA cho production.
  • Cách ly zone: SSID khách input=REJECT/không forward chéo → không chạm được LuCI/SSH/agent và không thấy nhau.

D · Kênh truyền & vận hành

  • SOCKS5 dùng socks5h (DNS resolve phía proxy) — đã dùng trong health-check & sing-box.
  • Nếu SOCKS không mã hoá đường tới nó, cân nhắc bọc thêm (chain qua TLS/WireGuard tới nhà cung cấp) để ISP không thấy đích.
  • Cập nhật firmware + sing-box để vá lỗi bảo mật (theo Bước 3 an toàn: backup ra máy trước).
  • Xoay token/device key/mật khẩu định kỳ; rà audit log (Cloud) xem có thao tác lạ.
